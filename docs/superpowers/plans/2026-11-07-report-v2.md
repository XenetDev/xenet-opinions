# Report v2 and Panel Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a finished run into a forwardable, structured focus-group report (card in chat, wide sheet, PDF/Word/Excel, share link), fed by a configurable panel, web research and a closing debrief of every participant.

**Architecture:** The web app's pre-run step gains web research (Exa) and a sized, grouped cast with persona sketches. The worker interviews every persona once after the last round (closing debrief), and after MiroFish's report it computes a structured `report_summary` with `gpt-4.1` from posts, comments, profiles and debrief answers; numbers are aggregated in code. The client renders a report card and a right-hand sheet from that event and exports it in the browser.

**Tech Stack:** Next.js App Router, AI SDK 7 (`generateText` + `Output.object`, `@ai-sdk/openai-compatible`), zod, Drizzle, Exa HTTP API, shadcn `Sheet`/`Tabs`/`Chart` (Recharts), `@react-pdf/renderer`, `docx`, `xlsx`.

**Spec:** `docs/superpowers/specs/2026-11-07-report-v2-design.md`

## Global Constraints

- Plans: Guest 10 participants, 3 rounds, 1 run lifetime; Free 10, 3, 1 a month; Starter ($10) 25, 5, 2 a period; Pro ($20) 50, 10, 2 a period.
- Models stay `gpt-4.1` (MiroFish and our calls). Our calls use the existing `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL_NAME` env.
- Group chips, in order: Customers, Prospects, Loyalists, Skeptics, Employees, Dealers/partners, Competitors, Investors, Regulators, Media, Influencers.
- Sentiment scale −5..+5. Action values: `act`, `not_act`, `unsure`, `n/a` (organisations). Action shares count people only.
- Closing debrief question (exact): "Thinking about everything discussed, what is your view of this decision? Would you go ahead with it yourself (buy, stay, accept, or whatever applies to you)? What is your single biggest concern?"
- No invented numbers: every count, share and average in the report is computed in code from per-persona classifications.
- Quotes must occur verbatim (case- and whitespace-insensitive) in that persona's posts, comments or debrief answer; otherwise dropped.
- Report step is best-effort: failure never fails the run or uses another run.
- Copy says "about N participants"; the cast is a target.
- `EXA_API_KEY` unset → web research off and its toggle hidden.

## Review Focus

- A run where some personas never post and the debrief times out for some: they appear as "no view", excluded from numbers, never invented. Test in Task 4 and Task 5.
- A finished run from before this change (no `report_summary`): still shows today's report, no card, no crash. Test in Task 6.
- A plan downgrade or stale client sending more participants than the plan allows: server refuses with `participants_exceeded`. Test in Task 1.
- The model returns a quote that is not in the source text, or a persona id it was not given: quote dropped, persona ignored. Test in Task 5.
- A share link for a deleted chat or a revoked token: 404, not a crash or leak. Test in Task 8.

### Task 5: Structured report summary

**Files:** Create `packages/engine/src/summary/{schema,classify,aggregate,generate}.ts`; modify `packages/engine/src/orchestrator/stages/report.ts`, `packages/engine/src/orchestrator/types.ts` (Deps gets `summarize`), `apps/worker/src/main.ts` (wire the model), `apps/web/src/app/api/chats/[id]/run/summary/route.ts` (retry), env/docs for the worker's `LLM_*`. Tests beside each.

**Interfaces:**
- Consumes: `agents`, `sim_feed` posts/replies, `debrief`, `report_text`, run `config.panel`, and the run's research sources, read through a new `store.getResearch(id: string): Promise<Research | null>` using `config.researchId`.
- Produces: event kind `report_summary` with `ReportSummary` (zod): `verdict`, `confidence` (`low|medium|high` + `reason`), `headline` (`sentiment`, `actShare`, `switchShare`, `topConcern { label, count }`), `split { positive, neutral, negative }`, `groups[] { id, label, people, sentiment, actShare | null, summary }`, `findings[] { title, detail, quote? { text, name } }` (3–5), `risks[]`, `opportunities[]`, `participants[] { agentId, name, age?, role?, location?, group, kind: 'person'|'organisation', sentiment | null, action, opinion, quote? }`, `sources[] { title, url }`, `method { participants, groups, rounds, webResearch }`, `writeup` (MiroFish markdown with blockquote runs collapsed: keep at most one quote per section); event kind `report_summary_failed { message }`.
- `classify(personas, texts, generate)`: batches of 10 personas, one structured call each, returns per persona `{ group, kind, sentiment, action, concern, quote }`; drops quotes not found verbatim; personas with no text → `sentiment: null`, `action: 'unsure'`, opinion "No view expressed".
- `aggregate(classified) → { headline, split, groups }`: pure; sentiment average over non-null; shares over people with action in `act|not_act|unsure`; `switchShare` = `not_act` share.
- `generate(...)`: one structured call for verdict, confidence, findings, risks, opportunities given the aggregates and a sample of quotes; numbers come from `aggregate`, never from the model.
- In `report.poll`, after `report_text`: run the summary with a 4-minute budget; on success emit `report_summary`, on any failure emit `report_summary_failed`; then advance to `finished` either way.
- `POST /api/chats/:id/run/summary` (owner only, latest run `done` without `report_summary`): runs the same summary in the web app and emits the event.
- [ ] Tests: aggregate on a fixture of 12 classified personas gives exact numbers (write them in the test); a fabricated quote is dropped; an unknown agent id from the model is ignored; personas with no text are "No view expressed" and excluded from averages; a model error emits `report_summary_failed` and the run still finishes; the retry route refuses non-owners and runs that already have a summary.
- [ ] Implement; add `LLM_*` to the worker env schema and docs; gates green; commit `feat: structured report summary`.
