# ReUI chat UI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the chat UI on ReUI primitives: a welcome home page with a working composer, a Branching-Thread-style conversation, an Agent-Activity-style run console, and a pill composer, with every existing behaviour intact.

**Architecture:** Client-only change under `apps/web/src`. ReUI primitives already live in `components/ui` and `components/reui`; the three block screens sit in `.context/reui-blocks/` as read-only references (copy markup patterns, never import them). New screen components go in `modules/chat/{console,thread,composer,home}`; `message-parts.tsx` becomes the thread's turn renderer; the data parts, routes and stream contract are untouched.

**Tech Stack:** Next 16, React 19, AI SDK 7 (`useChat`), Tailwind 4, ReUI primitives (`Message`, `Bubble`, `Marker`, `Frame`, `Attachment`, `Empty`, `InputGroup`, `Spinner`, `Progress`, `Badge`), streamdown, sonner, Vitest + Testing Library + vitest-axe, Biome.

**Spec:** `docs/superpowers/specs/2026-10-28-reui-chat-design.md`

**Foundations (done before Task 1 by the controller):** ReUI registry in `apps/web/components.json`; key in `apps/web/.env.local`; primitives committed; `components/blocks/*` moved to `.context/reui-blocks/`; `components/reui/code-block`, `ui/questionnaire.tsx`, `ui/svgs/` deleted; kept ReUI files formatted; `TooltipProvider` and `Toaster` in the root layout; lint, typecheck, tests, build green.

## Global Constraints

- Never import from `.context/reui-blocks`. Copy markup and class patterns; type everything (`noUncheckedIndexedAccess` is on).
- Data parts and routes are read-only: `data-stage`, `data-queue`, `data-sources`, `data-ontology`, `data-graph`, `data-agents`, `data-sim_feed`, `data-report_outline`, `data-report_event`, `data-interview`, `data-interview_window`, `data-error`, `text`; `POST /api/chats`, `POST /api/uploads`, `POST /api/chats/:id/messages`, `/run`, `/run/cancel`, `/run/retry`, `/run/report`, `/stream`.
- Stage titles (exact): ontology "Reading your documents", graph_build "Building the knowledge graph", sim_create "Creating the simulation", sim_prepare "Generating personas", sim_run "Running the simulation", interviews "Personas online", report "Writing the report", finished "Done". Console badges (exact): "Working", "Needs you", "Complete", "Failed", "Cancelled". Footer: `Step {n} of 7 · {m:ss}`; fold row: `Finished · {n} steps`.
- Composer placeholders (exact): run "Ask how people would react to…", follow-up "Ask the report…", interview "Ask the selected personas…". Disclaimer (exact): "Simulated opinions. Check important decisions with real people." Pause item label (exact): "Pause for interviews before the report". Rounds trigger: `{n} rounds` (`1 round`).
- Home copy (exact): title "Xenet Opinions", line "Ask how a group of people would react to a decision.", rails "Start" and "Resume", starters: "How will customers react to a 20% price increase on our Pro plan?", "What happens to public opinion if the city bans e-scooters downtown?", "How would employees respond to a return-to-office mandate?".
- Motion: live rows use `Spinner` + `shimmer`; new rows `animate-in fade-in-50 slide-in-from-bottom-1 duration-300 motion-reduce:animate-none`; no timers that fake progress.
- Every existing `data-testid` that a test outside the touched file relies on is preserved or the test is updated in the same task. Axe tests (`vitest-axe`) exist for every new screen component.
- Comments: none unless an invariant; single-line only. `pnpm lint`, `pnpm typecheck`, `pnpm test` (web) and `pnpm --filter web build` green at the end of every task.

## Review Focus

1. Reload mid-run and mid-interview-window renders the console in the right state (live row, Needs-you band, folded after report) from persisted parts alone. (Task 1 tests from fixtures; Task 6 browser)
2. The home composer never creates a chat until a file is attached or a message is sent, and a send ends on `/c/:id` with the run streaming. (Task 4 tests; Task 6)
3. Stop/Send slot: Stop cancels a run (with the existing cancel route) and only stops the stream for a follow-up; no second send while streaming. (Task 3 tests)
4. Interview selection, chips, "Select at least one persona" notice and Generate report still work inside the new console/composer. (Task 1, Task 3)
5. Reduced motion: every animation has `motion-reduce:animate-none`; the shimmer and spinner are the only live indicators. (Task 1, Task 2)
