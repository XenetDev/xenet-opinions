# Billing Implementation Plan

> **For agentic workers:** Executed natively (owner's deadline) with one whole-branch review at the end.

**Goal:** Sell Starter and Pro through Stripe Checkout, enforce monthly run and round allowances per plan, and show plans, usage and upgrade paths in the app.

**Architecture:** Plan limits live in one table in `@xo/engine`. A `subscriptions` row mirrors Stripe, re-fetched on every webhook. A `run_usage` ledger, written when a root run is created, is counted against the plan's period. With no `STRIPE_SECRET_KEY`, nothing changes.

**Tech Stack:** Next.js App Router, Drizzle, Better Auth, `stripe` SDK, Stripe Checkout and Customer Portal.

**Spec:** `docs/superpowers/specs/2026-11-03-billing-design.md`

## Global Constraints

- Guest 1 run lifetime, 3 rounds. Free 2 runs per UTC calendar month, 3 rounds. Starter 4 runs per billing period, 5 rounds. Pro 6 runs per billing period, 10 rounds.
- Lookup keys `starter_monthly` and `pro_monthly`.
- Retries and restarts are free and need no allowance.
- `active`, `trialing` and `past_due` are paid. Everything else is Free.
- Secrets only in env; `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` also in `turbo.json`.

## Review Focus

- A webhook arriving late, twice, or for an old cancelled subscription after a new one: the current plan must win. Test in Task 2.
- A user who has already run this month before subscribing, and existing users at migration: the ledger backfill must count past runs. Test in Task 1.
- Renewal webhook missed: an expired period must re-sync, not block a paying user. Test in Task 2.
- Double-click on Upgrade, or Upgrade while already subscribed: never two subscriptions. Test in Task 3.
- Guest signs in with a used run: the usage moves with them and is not lost. Test in Task 1.

### Task 1: Plans, tables, ledger
Files: `packages/engine/src/policy/plans.ts`, `packages/db/src/schema/billing.ts`, migration with backfill, `apps/web/src/server/runs.ts` (`startRun` writes `run_usage`), `apps/web/src/server/account.ts` (relink moves it).

### Task 2: Stripe sync and webhook
Files: `apps/web/src/server/billing/{stripe,sync,allowance}.ts`, `apps/web/src/app/api/billing/webhook/route.ts`. `syncSubscription(id)` re-fetches and upserts; a cancelled subscription never overwrites a different live one.

### Task 3: Checkout, portal, deletion
Files: `apps/web/src/app/api/billing/{checkout,portal}/route.ts`, `apps/web/src/lib/auth.ts` (cancel before delete), `scripts/stripe-setup.mjs`, env schema, `.env.example`, `docs/hosting.md`, `turbo.json`.

### Task 4: Gate and limits
Files: `apps/web/src/server/{limits,run-gate,usage,usage-from}.ts`, pages and layout use the resolved limits. Plans path only when billing is on.

### Task 5: UI
Files: `apps/web/src/app/(chat)/pricing/page.tsx`, `apps/web/src/modules/billing/*`, usage card, account menu, sidebar, header title, `send-notices.ts`.

### Task 6: End-to-end check
Local dev with `stripe listen`, a test card, then upgrade, usage, limit, portal and cancel.
