# Accounts and sign-in implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Magic-link, Google and GitHub sign-in on top of the existing anonymous Better Auth setup, with anonymous history and quota carried into the account, quotas of 1 (anonymous) and 3 (registered) runs per 24 hours, a ReUI `auth-3` sign-in page, an account menu, and hardened server defaults.

**Architecture:** Better Auth 1.7 keeps the `anonymous` plugin and gains `magicLink` plus built-in social providers, all env-gated in `apps/web/src/lib/auth.ts`. The anonymous plugin's `onLinkAccount` hook reassigns `chats`, `runs` and `uploads` to the registered user inside one transaction before the plugin deletes the anonymous row, so `runsStartedSince(userId)` keeps counting one person's runs. `getSessionUser` returns `isAnonymous`, `getLimits(user)` picks the quota, and the UI reads provider availability as booleans. Rate limits live in a new `rate_limit` table.

**Tech Stack:** Next 16 App Router, React 19, Better Auth 1.7.11 (`anonymous`, `magicLink`, social providers, database rate limiting), Drizzle 0.45 + Postgres, Resend HTTP API via `fetch`, ReUI `auth-3` markup on shadcn primitives (`Field`, `Input`, `Button`, `Separator`, `Item`, `Avatar`, `DropdownMenu`, `AlertDialog`, `Alert`), Zod 4, Vitest + Testing Library + vitest-axe, Biome.

**Spec:** `docs/superpowers/specs/2026-10-28-auth-design.md`

## Global Constraints

- Env names (exact): `RESEND_API_KEY`, `EMAIL_FROM`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `APPLE_CLIENT_ID`, `APPLE_CLIENT_SECRET`, `APPLE_APP_BUNDLE_IDENTIFIER`, `MAX_RUNS_PER_DAY_ANONYMOUS` (default `1`), `MAX_RUNS_PER_DAY` (default becomes `3`).
- Magic link: `expiresIn: 900`, `storeToken: 'hashed'`. Rate limits: global `window: 60, max: 60`; `/sign-in/magic-link` `window: 60, max: 3`; `/sign-in/anonymous` `window: 60, max: 10`; `/delete-user` `window: 60, max: 3`; `storage: 'database'`; `enabled: true` in every environment. Sessions: `expiresIn: 60*60*24*30`, `updateAge: 60*60*24`. No cookie cache.
- `next` is accepted only as a path: starts with `/`, second char not `/` or `\`, no `:` before the first `/`-segment end (no scheme). Anything else becomes `/`.
- Copy (exact): sign-in title "Sign in"; subtitle "Enter your email to get a sign-in link."; field label "Email"; description "Your link stays active for 15 minutes."; button "Send sign-in link"; divider "Or continue with"; buttons "Continue with Google", "Continue with GitHub", "Continue with Apple"; sent state title "Check your email", body "We sent a sign-in link to {email}.", link "Use a different email"; expired notice "That link has expired or was already used. Request a new one."; no-provider title "Sign-in is not set up on this instance", link "Continue without signing in"; right panel headline "Ask how people would react before you decide.", line "Attach a few documents, ask a question, and watch a simulated public form an opinion.", three bullets "More runs a day than a guest", "Your conversations on every device", "Pick up a chat later, wherever you are"; usage-bar link "Sign in for {N} runs a day"; anonymous quota notice "You've used today's free run. Sign in for {N} runs a day, or come back tomorrow."; header button "Sign in"; menu items "Sign out", "Delete account"; delete dialog title "Delete your account?", body "We'll email you a confirmation link. Your conversations and uploads are removed once you confirm.", confirm "Send confirmation email"; toast "Confirmation email sent".
- Email (exact): subject "Your sign-in link for Xenet Opinions"; delete subject "Confirm deleting your Xenet Opinions account".
- No secret, token or link is ever written to logs in production; the console mailer is refused when `NODE_ENV === 'production'`.
- Comments only for invariants, single line. `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm --filter web build` green at the end of every task. Route tests that mock `@/lib/session` return the full `SessionUser` shape.

## Review Focus

1. A magic-link verification whose `callbackURL` is off-origin, or a `next` like `//evil.com` or `javascript:` must land on `/`. (Task 3 `sanitiseNext` table; Task 5 page test)
2. Linking must be all-or-nothing: if reassigning rows throws, the sign-in fails and the anonymous user and its chats still exist. (Task 2 db test with a failing transaction)
3. A returning registered user signing in from a new anonymous session with zero chats must not lose anything and must not get a duplicate row; a registered user hitting `/sign-in` is sent to `next`. (Task 2 test with an empty anonymous user; Task 5 redirect test)
4. The console mailer must never run in production, and a production env without `RESEND_API_KEY` must simply hide the magic-link option. (Task 1 env and providers tests)
5. Sign-out from a chat page must not leave the UI showing the old user's chats: the header and the list refresh, and the next anonymous session starts empty. (Task 6 test that `signOut` is followed by `push('/')` and `refresh()`; Task 7 browser)
